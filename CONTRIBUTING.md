# Contributing to xxHub

Thank you for your interest in contributing to xxHub! We welcome contributions from everyone.

## How to Contribute

### 1. Fork the Repository

Click the "Fork" button at the top right of the repository page.

### 2. Clone Your Fork

```bash
git clone https://github.com/your-username/xxhub.git
cd xxhub
```

### 3. Create a Branch

Create a feature branch for your changes:

```bash
git checkout -b feature/your-feature-name
```

### 4. Make Changes

Make your changes to the codebase. Please follow the code style guidelines below.

### 5. Commit Your Changes

Use descriptive commit messages:

```bash
git add .
git commit -m "feat: add new feature"
```

### 6. Push to Your Fork

```bash
git push origin feature/your-feature-name
```

### 7. Create a Pull Request

Go to the original repository and click "New Pull Request".

## Code Style Guidelines

### PHP

- Follow PSR-12 coding standards
- Use 4 spaces for indentation
- Use snake_case for function names and variables
- Use PascalCase for class names
- Add type declarations where possible
- Include docblocks for functions and classes

### JavaScript

- Use ES6+ syntax
- Use 2 spaces for indentation
- Use camelCase for function names and variables
- Use const/let instead of var
- Add comments for complex logic

### CSS

- Use BEM naming convention
- Use 2 spaces for indentation
- Use kebab-case for class names
- Use CSS variables for colors and spacing
- Keep selectors specific but not overly complex

## Pull Request Guidelines

1. **Description** - Provide a clear description of what your PR does.

2. **Tests** - Include tests if applicable.

3. **Screenshots** - If your changes affect the UI, include screenshots.

4. **Related Issues** - Reference any related issues (e.g., "Fixes #123").

5. **Checklist**:
   - [ ] Code follows the style guidelines
   - [ ] Tests pass
   - [ ] Documentation is updated
   - [ ] No console.log statements left in production code

## Reporting Issues

If you find a bug or have a feature request, please create an issue with:

1. A clear title
2. A detailed description
3. Steps to reproduce (for bugs)
4. Expected behavior
5. Actual behavior
